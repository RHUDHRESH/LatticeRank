# 10 — Architecture Freeze (DriftForge v2)

**Status:** frozen for Phase 2, subject to the E0/E2/E5/E8 stop-gates in `09`.
**Verdict on the provisional architecture:** it **survives contact with evidence, with two
structural corrections and one demotion.**

---

## 1. Did the provisional architecture survive falsification?

The Phase-1 brief asked for an attempt to falsify the proposed pipeline. Results:

| Provisional element | Falsification attempt | Outcome |
|---|---|---|
| Lattice estimator | Naive FFT prototype **failed** — locked onto the 31 px routing period, not the 2.8–17 px device lattice | **Survived after correction.** High-pass + bounded period search + harmonic scoring recovers 18/20 (x), 19/20 (y), with all failures self-flagged at low confidence |
| Lattice candidate expansion | Is the alias set the naive rectangular grid? | **Corrected.** It is the **centred-rectangular** lattice — contacts are on a checkerboard, so only `m+n` even translates preserve the pattern. All 4 measured aliases satisfy this. Expanding on the naive grid wastes half the budget |
| Photometric/ZNCC expert | Is it still worth keeping? | **Survived, demoted.** Best single leak-free channel (45%), but a poor *selector* — its global arg-max is the failure mechanism |
| Mid-band channel | Does it carry real signal? | **Survived, demoted hard.** Leak-free it is the **worst** channel (15%); its fixed 0.75 weight was tuned to the generator leak. Retained only as a ranker feature |
| Directionality expert | Does it reduce aliasing? | **Partially falsified.** On a uniform array the orientation field is as periodic as the intensity field. Demoted from anti-alias component to robustness channel (SHOULD HAVE) |
| Phase correlation | Can it locate? | **Falsified as a locator** — produces the same peak lattice. **Survived as a transform estimator**, where periodicity actually helps |
| Siamese reranker | Is it justified now? | **Not yet.** No trained model, no leak-free training data. Demoted to EXPERIMENTAL, gated on E0 |
| Meta-ranker | Is there headroom? | **Survived.** Leak-free oracle-of-2 (45%) beats fixed fusion (30%) by 15 points; disagreement 14/20 |
| Equivalence set + centre rule | Is the current tie rule sound? | **Falsified.** Applied to an NMS-decimated set with an uncalibrated absolute margin. Rebuilt on calibrated probabilities |
| Architecture classifier | Justified? | **Cut.** No supporting evidence; adds a failure mode |

## 2. The frozen v2 pipeline

```
Reference (1000x1000, 1 nm/px)        Search (1000x1000, 10 nm/px)
        |                                      |
        +--------------+-----------------------+
                       v
        [S1] SHARED PREPROCESSING
             robust contrast (0.5/99.5 pct); one unified decimation
             function used by BOTH the classical path and any learned
             path (fixes R10)
                       |
                       v
        [S2] TRANSFORM ESTIMATOR            <- replaces the 5x5 brute-force bank
             log-polar / phase correlation -> (rotation, scale) + confidence
             fallback: coarse-to-fine bank if E3 fails
             cost: ~2-6 NCC calls instead of 50            [fixes R6]
                       |
                       v
        [S3] EVIDENCE CHANNELS (computed once, at the estimated transform)
             A. ZNCC on robust-contrast intensity      (best single channel)
             B. ZNCC on mid-band (sigma3 - sigma15)    (boundary/context)
             C. ZNCC on edge-directionality maps       (polarity/gamma invariant)
                D = (m*cos 2*theta, m*sin 2*theta)
                       |
                       v
        [S4] LATTICE ESTIMATOR
             high-pass residual -> bounded period search (2.5-30 px)
             -> harmonic-summed scoring -> (pitch_x, pitch_y, orientation, confidence)
             GATE: low confidence => skip S5 expansion, widen the equivalence set
                       |
                       v
        [S5] CANDIDATE GENERATION
             seeds: NMS peaks from each channel (NMS kept as a SEED finder only)
             expansion: for each seed, translates on the CENTRED-RECTANGULAR
                        lattice generated by (2*pitch_x, 0) and (pitch_x, pitch_y)
             => the hypotheses NMS destroyed are restored explicitly   [fixes H1]
                       |
                       v
        [S6] CANDIDATE EVIDENCE TABLE  (one row per candidate, <= ~50 rows)
             zncc_score, midband_score, directionality_score,
             lattice_residual, lattice_confidence, psr, best_second_gap,
             expert_vote_count, scale_consistency, rotation_consistency,
             noise_estimate, blur_estimate, local_entropy, boundary_context_score
             *** distance-to-centre is NOT a feature ***               [fixes R5]
                       |
                       v
        [S7] META-RANKER (HistGradientBoosting)
             -> calibrated P(candidate is the true match)
             (optional S7b: Siamese reranker on the top-k, EXPERIMENTAL, gated on E0)
                       |
                       v
        [S8] EVIDENTIAL EQUIVALENCE SET
             admit i if p_i >= p_max - delta, delta calibrated on validation
             so the set contains the true cell at a target rate (~99%)
                       |
                       v
        [S9] OFFICIAL TIE RULE
             among the equivalence set ONLY, choose the candidate nearest
             the Search centre                                    [official req. #3]
                       |
                       v
        [S10] SUB-PIXEL REFINEMENT
              upsampled-DFT refinement of the SELECTED cell only
              (never before selection)
                       |
                       v
             (x, y)  + confidence  -> stdout "x,y"   (never abstains)   [fixes R11]
```

## 3. Interfaces and data contracts

| Stage | Input | Output |
|---|---|---|
| S1 | 2 × uint8 1000² | 2 × float32 normalised; shared decimation fn |
| S2 | ref, search | `Transform{rotation_deg, scale, confidence}` |
| S3 | ref, search, transform | 3 × float32 response maps (valid-mode NCC) |
| S4 | search | `Lattice{pitch_x, pitch_y, orientation, confidence}` |
| S5 | response maps, lattice | `list[Candidate{x, y, seed_channel, lattice_offset(m,n)}]`, ≤~50 |
| S6 | candidates, maps, lattice, transform | feature matrix `(n_candidates, ~14)` |
| S7 | feature matrix | calibrated `p` per candidate |
| S8 | p vector | `EquivalenceSet ⊆ candidates` |
| S9 | equivalence set, search shape | one candidate |
| S10 | selected candidate, maps | `(x, y)` float |

## 4. Why each component exists — one line, traced to evidence

| Component | Justification |
|---|---|
| S1 shared preprocessing | R10: `ml.py` and `baseline.py` currently decimate differently |
| S2 transform estimator | R6: 79.6% of 3.69 s/pair is the 50 NCC calls of the brute-force bank |
| S3-A ZNCC | Best single leak-free channel (45% @5px); sponsor baseline metric |
| S3-B mid-band | Carries mat/boundary context — the strongest *non-leaked* cue (`05` §4.2) |
| S3-C directionality | Ref/Search draw `edge_strength` and `gamma` independently; orientation is invariant to both (US20160035076A1 concept) |
| S4 lattice estimator | Doubek et al.: repetitive-pattern ambiguity must be modelled explicitly; prototype recovers 18/20, 19/20 |
| S5 lattice expansion | H1: NMS collapses 4.4–67 genuine hypotheses per cell; restores them explicitly |
| S6 evidence table | H4: expert disagreement 14/20 leak-free; fixed weighting is provably wrong |
| S7 meta-ranker | Oracle-of-2 beats fixed fusion by 15 points leak-free |
| S8 equivalence set | Current `tie_delta=0.015` is an uncalibrated absolute NCC margin (`03` D3) |
| S9 centre rule | Official requirement #3, applied where it belongs — after equivalence |
| S10 sub-pixel | Predictions are half-integer quantised; median 0.52 px is the floor |

## 5. Components explicitly rejected

Architecture classifier/gating · distance-to-centre as a ranker feature · abstention in the
submitted path · phase correlation as final locator · retuned fixed fusion weights ·
XGBoost · full-image deep heatmap regression · softening the generator's periodic ambiguity.
Rationale for each in `08` §3.

## 6. Unresolved questions

1. **Signature disposition (E0)** — delete, de-correlate, or make probabilistic?
   Recommendation 0b (de-correlate). **Requires human decision.**
2. **Phase-2 deliverable dates** — the official page shows a 24 Jul – 18 Sep 2026 roadmap
   but no labelled Phase-1/Phase-2 deadlines. Must be re-checked before scheduling.
3. **Does lattice confidence generalise?** Validated on n=20. E2 must confirm at n≥200 and
   on sponsor data before the gate in S4 can be trusted.
4. **Is ~45% the classical ceiling?** If E6/E7 cannot exceed the leak-free oracle, the
   learned reranker moves from EXPERIMENTAL to necessary.
5. **`supersample=2` vs `4`** — is some measured aliasing a rendering artifact? (E1b)
6. **True-cell recall after expansion** — the hard ceiling on everything downstream (E5).

## 7. Implementation order

1. **E0** — neutralise the signature; re-baseline. *Nothing else is interpretable first.*
2. **E1** — expand the gate to ≥200 pairs; fix R8; withdraw the 80% claim.
3. **E2** — harden the lattice estimator; calibrate its confidence.
4. **E5** — lattice candidate expansion; measure true-cell recall (must reach ≥99%).
5. **E3** — transform estimator; reclaim the runtime budget.
6. **E6** — leak-free channel ablation incl. directionality.
7. **E7** — meta-ranker + calibrated equivalence set + centre rule.
8. **E8** — cross-generator validation. **Must beat sponsor ZNCC on sponsor data.**
9. **E10** — public repo, clean-machine inference test, per-parameter citations.
10. **E11** — sub-pixel refinement.
11. **E9** — learned reranker, only if E7 leaves a gap and E0/R10 are closed.
